# SobStage code audit — 7 September 2026

> **Status, 8 September 2026 (v1.10.0):** fixed and verified — C1, C2, H1, H2,
> H3, H4, H5, H6, H7, M1, M3, M8, M9, L1, L2. Each has a test that failed
> before the fix, and C1 was reproduced and re-run end to end through the
> real app (`Tools/e2e_app_take.sh`). Still open: H8–H12, M2, M4–M7,
> M10–M17, L3–L12.

Audited at `main` = `23731f5` (v1.9.0). Five reviewers read the code by area
(audio core, storage and recovery, platform backends, application layer, UI
and delivery). Every finding marked **verified** was then confirmed by a
second reading of the cited lines; **plausible** means the mechanism is
present in the code but the consequence depends on OS behaviour that cannot
be reproduced on the CI machines.

Mechanical checks run on this commit: the 425 unit tests, `sim_coreaudio`
(44 checks), `sim_wasapi` (43), `sim_capture_mac`, `e2e_capture` and a short
`soak_drift` were all built with `-fsanitize=address,undefined` and
`-Wall -Wextra`. All pass with no memory errors and no leaks. One compiler
warning and two UBSan reports came out, listed below.

## Summary

The engineering under the hood is strong: the audio thread is genuinely
free of allocation, locks and I/O; the drift loop, pre-roll, reconnect and
layout-freeze logic are correct and tested; the writer, recovery, naming and
capacity policies are correct in isolation; the JSON and ffmpeg boundaries
are safe. The defects cluster at seams the tests cannot reach: the moment
the headphone output stops being the clock, the assumption that one device
is one channel, the order in which a take is armed, and OS behaviour the
simulators flatten. Two findings are critical because they lose or corrupt a
whole take silently. Neither is architectural; each is a small fix.

Counts: 2 critical, 12 high, 17 medium, 12 low.

## Critical

### C1. Recording only runs while the headphone output is running — verified
`Source/Core/CaptureCoordinator.cpp:138` is the only caller of
`processOutputBlock`, which is the only thing that pulls the per-microphone
rings and feeds the writer. Consequences:

- With no output device selected ("No headphones found"), `startMonitoring`
  opens the microphones only. Meters stay flat, and nothing blocks the
  record button (`Application::getRecordDisabledReason` does not check it).
  A take records header-only files and the verdict blames the app.
- Mid-take, if the output device is unplugged, `Application::restartCapture`
  (`Application.cpp:345`) returns early because a take is running, no stream
  is reopened, `framesDropped` stays 0, the elapsed clock keeps counting, and
  the rest of the take is silence with no pop-up.

Fix: gate arming on an open output stream; on output loss mid-take either
reopen the output alone or pull the rings from a fallback timer; surface
"output stopped" in `TakeHealth` so the mid-take card fires.

### C2. 32-bit takes are corrupt files — verified
`Source/Core/SessionWriter.cpp:160-170` packs samples as 16-bit or "else
24-bit (3 bytes)". The header, byte rate, block align and the byte counters
all use `bitDepth / 8` = 4 (`:70, :94-96, :133`). Settings offers 32-bit and
`Application::setBitDepthOverride` accepts it (`Application.cpp:2451`), and
the choice is re-applied from settings at launch (`:2395`). Every stem and
the mix get a 32-bit header over a 3-byte sample stream: the data chunk
overstates the bytes on disk, players decode noise, and recovery "repairs"
with the wrong block align. No test covers 32-bit.

Fix: implement 32-bit packing, or refuse 32 in `SessionWriter::open` and
remove it from the picker until it is implemented.

## High

### H1. Ring-buffer overrun drops audio without counting it — verified
`Source/Core/DeviceInputStream.cpp:43` discards the return of `ring.write`.
When the 8-block ring is full the newest samples are thrown away and both
`getUnderrunSamples()` and `getFramesDropped()` still read 0, so §0.1's
"never lose audio silently" has a hole. Fix: count the shortfall into an
atomic and surface it in `TakeHealth`.

### H2. Unplugging a multi-input interface mid-take only silences socket 1 — verified
`Source/Core/CaptureCoordinator.cpp:296-311` returns after the first
channel whose `deviceId` matches, but every input of an interface shares
that id. Sockets 2..N keep `channelLive == true`, write a held sample for
the rest of the take, and on reconnect only socket 1 restarts cleanly; the
others replay stale ring contents. Fix: apply to every matching channel.

### H3. The first take of every launch is never mirrored — verified
`Application.cpp:1133` decides the mirror folder from
`mirrorPolicy.isMirroring()` before `reset()` and `evaluateAtArm()` run at
`:1177-1182`, and `MirrorPolicy` starts in `DisabledByUser`
(`MirrorPolicy.h:52`). Take 1 has no backup even though the save prompt
promised one; later takes inherit the previous take's verdict. Fix: move
the reset and evaluation above `createMirrorFolder`.

### H4. Mirror folder name collisions truncate the backup — verified
`Application::createMirrorFolder` (`Application.cpp:1895-1907`) does no
collision resolution and `SessionWriter` opens with `trunc`. Collision
handling exists only against the card. The card-removal flow makes this
likely: card pulled, app promises the mirror copy is safe, user starts the
next take on a new destination with the same folder name, mirror files are
zeroed. Fix: resolve collisions against the mirror root too.

### H5. Changes refused mid-take are never applied after the take ends — verified
Nothing in the stop path (`Application.cpp:1188-1270`) calls
`restartCapture()`. A mic plugged in mid-take ("It'll be recorded starting
with your next take"), an unplug, a rename or a rate change all stay
unapplied: the next take's plan shows N+1 strips and files while the frozen
capture channel list writes N stems. Fix: set a dirty flag wherever
`restartCapture` bails on `isRecording()` and restart at the end of stop.

### H6. Trim sliders index a different space from the strips — verified
`Application::setChannelTrimDb` / `getChannelTrimDb`
(`Application.cpp:1666-1720`) walk included devices, while the UI passes
strip (channel) indices and `capture->setChannelTrimDb` takes channel
indices. On any multi-input device the persisted trim lands on the wrong
device and the slider snaps back. Fix: resolve the strip index through the
channel plan to `(deviceKey, deviceChannel)` as `setMicAssignedName` does.

### H7. Unticking a mic in Settings mid-take silences it as an "unplug" — verified
`Application.cpp:625-628` builds the mid-take "present" set from
`d.included`, which the Settings tick box also flips. The next device-list
notification (macOS fires these for any audio device) marks the channel
dead and it writes silence for the rest of the take. Fix: build presence
from enumeration, and refuse mic toggles while recording.

### H8. The app's own combined device is enumerated as a microphone — plausible
`CoreAudioBackend::enumerateDevices` (`CoreAudioBackend.cpp:436-462`) only
special-cases the built-in transport; the "SobStage" aggregate device
presents input channels and is listed as a mic, and new devices default to
included. Publishing the aggregate fires the device-list listener, which
includes the aggregate and republishes with itself as a sub-device. Fix:
skip the aggregate transport type or `kOurAggregateUid` in enumeration, and
make `publish()` a no-op when the sub-device list is unchanged.

### H9. Windows enumeration reports no channel count or rates — verified
`WasapiAsioBackend.cpp:354-359` leaves `maxInputChannels`,
`supportedSampleRates` and `currentSampleRate` unset. Every Windows
interface is one channel and the rate negotiator has no votes. Fix: query
`GetMixFormat` and probe `IsFormatSupported` per device.

### H10. Sample-rate change confirmed by an immediate read-back — plausible
`CoreAudioBackend.cpp:226-232` writes the nominal rate and reads it back in
the same call; the HAL applies it asynchronously on many USB devices, so a
change that is succeeding is reported as refused and the take will not
start. The fake applies the write synchronously, so the test passes for the
wrong reason. Fix: poll for up to ~500 ms or listen for the property change.

### H11. No per-device CoreAudio listeners — verified (consequence plausible)
Only the system device-list property is observed. A rate change by another
app, a device dying, or a processor overload during a take goes unnoticed;
the writer keeps stamping the old rate. Fix: listen for
NominalSampleRate, DeviceIsAlive and ProcessorOverload on open devices.

### H12. Tab can walk out of a modal card to the Record button — verified
`ModalCard` sets `setWantsKeyboardFocus` but no focus container, and the
screen beneath stays enabled. Shift+Tab from a card reaches Mute, then
Record; pressing it stacks a second card. Fix:
`setFocusContainerType (keyboardFocusContainer)` on cards and disable the
main viewport while one is up.

## Medium

- **M1. Pipeline hand-off memory ordering** — verified.
  `CaptureCoordinator.cpp:287-290` vs `:526-528` uses a store-release then
  load-acquire handshake, which is Dekker-style and needs `seq_cst`. Safe on
  Apple Silicon by architecture; a nanosecond use-after-free window on Intel
  and Windows when stopping a take.
- **M2. Stereo collapse ignores disabled sockets** — verified.
  `CaptureCoordinator.cpp:218-228` applies the §2.1 analysis to inputs 0/1
  whenever one channel is taken at socket 0, even on a 4-input interface
  with sockets 2..4 disabled; a signal on a disabled socket can be recorded
  into the stem.
- **M3. "Drive is full. Recording has stopped" does not stop** — verified.
  `Application.cpp:2178`. The take continues until a write fails, which
  then arrives as the card-removal notice. Also `-1` (unknown free space)
  is treated as exhausted.
- **M4. No `fsync` anywhere** — verified. "Saved" is shown while the tail
  and final header are still in the OS cache; a card pulled without eject
  keeps a header up to 5 s stale.
- **M5. Preflight measures the page cache** — plausible. The 200 MB
  benchmark never syncs inside its windows, so a slow card can pass at RAM
  speed. Also the gate passes when no result exists and a second preflight
  is dropped while one runs (`Application.cpp:1537-1559`).
- **M6. 90 % ring rule assumes the mirror protects the stems** — verified.
  Card, mirror and mix are written serially on one writer thread
  (`WritePipeline.cpp:353-382`); with the mirror active the app only warns,
  and a full ring drops blocks from both copies.
- **M7. Split files** — verified. First file is unnumbered, and every
  continuation carries `TimeReference = 0` (`SessionWriter.cpp:105-113,
  189`), so a DAW stacks `_001` at the session origin. Splitting is
  admittedly untested.
- **M8. Disabled-mic memory is dropped on unplug** — verified.
  `saveSettings` rebuilds `disabledMicKeys` from connected devices only
  (`Application.cpp:2504-2506`); cameras are merged, mics are not.
- **M9. Quit mid-take leaves no stop timestamp** — verified. The next
  launch shows a recovery dialog for a take that was closed cleanly, and
  `TakeCombiner`'s destructor can block quit for minutes.
- **M10. DriftCompensator read/written from both threads** — verified;
  practical impact low.
- **M11. COM initialised in the wrong apartment on Windows** — verified.
  `CoInitializeEx(MULTITHREADED)` on JUCE's STA message thread returns
  `RPC_E_CHANGED_MODE`, ignored, then `CoUninitialize` pops JUCE's own
  initialisation at quit.
- **M12. Any installed ASIO driver disables the exclusive-mode preflight**
  — verified. `preferAsio` short-circuits the WASAPI probe though no ASIO
  path exists.
- **M13. WASAPI open failures carry no reason** — verified. Only the
  "no format" branch sets `lastOpenError`; a 64-frame request below the
  device's minimum period fails silently.
- **M14. ALSA hot-plug thread cannot be stopped** — verified. `close()` does
  not wake a blocked `read()` on Linux; quitting can hang.
- **M15. Output picker blanked twice a second** — verified.
  `MainComponent.cpp:840` passes an empty selection and `fillCombo` clears
  unconditionally.
- **M16. Message-thread I/O in the refresh loop** — verified. Volume
  enumeration with `statvfs` on every mount at 2 Hz while Settings is open;
  three or four free-space calls and a per-file `stat` of the session folder
  on every tick during a take; camera enumeration every 2 s during a take;
  a failed camera open retried twice a second forever.
- **M17. 60 Hz tick rebuilds the channel plan per strip per frame** —
  verified. `rebindMeters()` every frame calls `getMicDisplayName` and
  `getMicProductName`, each of which rebuilds the plan.

## Low

- **L1. UBSan: `SampleFormat.h:45` left-shifts a negative value** in the
  24-bit decode (undefined in C++17, benign on current compilers). Fix by
  shifting as unsigned.
- **L2. `-Wdelete-non-virtual-dtor` at `WasapiAsioBackend.cpp:42`**:
  `DeviceNotificationClient` deletes itself through a class with no virtual
  destructor. Mark it `final` or add one.
- **L3. Drift settling.** `soak_drift` at 72 s ends with a 1.19 ms
  inter-channel spread (ceiling 1 ms); at 180 s it is 0.04 ms and at 15
  minutes 0.02 ms. The slew limit makes the first two minutes of a take
  exceed the ceiling; steady state is fine.
- **L4. Oversized output slices are dropped silently** when more than 2×
  nominal (`CaptureCoordinator.cpp:67-69`), and the CoreAudio input path
  shifts channel indices on an oversized buffer.
- **L5. MonitorBus mute/runaway flags are shared non-atomically.**
- **L6. Dry-ring hold emits DC and under-counts by one sample per block.**
- **L7. Recovery can loop forever on a corrupt fmt chunk size**
  (`SessionRecovery.cpp:215`, arithmetic in 32-bit); odd data chunks lack
  the RIFF pad byte.
- **L8. Record press silently no-ops when the session folder cannot be
  created** (`Application.cpp:1136-1146`).
- **L9. Output candidates all flagged "appeared after launch"** on every
  device change, so the selector's priority degrades to enumeration order.
- **L10. Workflows use mutable action tags and grant `contents: write` to a
  third-party release action**; no checksums or attestation on release
  assets; JUCE fetched by tag not commit; the JUCE cache key collides
  between CI and release. No expression injection was found.
- **L11. README numbers have drifted**: "260 unit tests" at line 687, the
  per-area table, "79 checks", and the claim that both simulators run under
  ThreadSanitizer (only `sim_wasapi` does).
- **L12. Keyboard focus is invisible and mic rename is mouse-only**; the
  rename dialog captures a raw strip index across a hot-plug.

## What is sound

No allocation, lock, log or I/O on any audio-thread path in Core or the
backends. Metering pointer rebinds across capture rebuilds are correct and
on the message thread. OS device callbacks are marshalled with `callAsync`
behind a liveness token. The `activePipeline` busy-count hand-off is the
right design (only its ordering is wrong). WAV 16/24-bit packing, RIFF
sizes under the 3.9 GB split, bext fields, naming and collision rules on the
card, and header repair on recovery are all correct. `JsonValue::parse`
never crashes on garbage. The ffmpeg command is an argv, not a shell string.
The test framework has real assertions and exit codes; every simulator
fails non-zero. The release pipeline is honest about signing.

2. H3, H4, H5, H6, H7 (arming order and the three channel spaces).

5. The rest, with the UI refresh-loop work (M15-M17) as one change.
